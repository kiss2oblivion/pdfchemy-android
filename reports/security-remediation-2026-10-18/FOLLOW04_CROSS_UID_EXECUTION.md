## Correction and compatibility

ExternalUriAdmission resolves the installed provider identity and rejects content URIs owned by the host UID. It strips the decoded user qualifier before resolution, including encoded `0%40` input. Neither a provider-name suffix nor a forgeable Intent grant flag confers authority. External providers retain Android-enforced read grants.

Supported app-owned document opens use an explicit activity alias with `exported=false`, targeting MainActivity. Android authenticates this route before delivery. MainActivity recognizes its explicit component and own-provider URI; public MainActivity Intents and forged extras remain subject to external admission. DocumentActions uses this route for PDF/EPUB/comic inputs. Audio and other MIME types retain ordinary viewer Intents and read grants. Outgoing sharing continues to grant the selected external receiver access; a foreign re-import of an app-owned provider through the public entry is refused.

New native checks run under the real foreign UID and additionally require Android to deny a direct private-alias launch with SecurityException containing `not exported`. The positive internal control calls the actual DocumentActions.view action and requires real delivery plus byte-identical automatic staging. The test APK contains the sender Activity and receipt/read providers; release hygiene rejects these classes in production DEX and verifies the internal alias is private.
